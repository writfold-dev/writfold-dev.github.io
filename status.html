02 / Roadmap

Done, next, and not planned

What is done is listed in full above.

  1. The four questions

    Read and write verbs, the index, pinned citations, external checkers and the Claude Code plugin. Done

  2. Runs, gates and delivery drafts

    Receipts tied to exact bytes, instruction and checklist gates, Splicery edits, delivery drafts and your own modes. Done

  3. The run graph, guards and proposals

    Plans with splicing and required steps, guard rules, proposals, the closing reflection, and proofs of three decision kernels. Done

  4. writfold watch and Tuft search

    The plan map with an inspector and a calm default frame; Tuft with a one-line search, several repositories and symbols. Done

  5. One week of real use

    Count what the checks caught, and what was waived, before adding more. Next

  6. Check receipts other machines can read

    A tracked record of what a checker found, so a machine without the checker or its credentials can read when a citation was last checked. Planned

  7. A delivery mode as a step’s gate

    A plan step that owes a checked draft. Planned

  8. Trailer and tracker edges, and --at

    Links read from commit trailers and tracker references, and answers as of a given commit. Planned

  9. An MCP server

    Deferred until a harness without a shell needs one. The CLI and the plugin are the interface. Deferred

  10. A governed profile

    Authority levels, exception routes and signing. Writfold stays single user with cooperating agents. Not planned

04 / FAQ

Common questions

Can I use Writfold today?

Yes, as a preview: download the binary and install the plugin. Single user, cooperating agents, local clones (plus any external checkers you install), Linux x86_64 or WSL2.

Does it need a server or a database?

No. One static binary, records in Git, and a local index that Writfold derives and can always rebuild.

Does Writfold run or schedule my agent?

No. It records the plan and what met each gate. The agent reads the current step, does the work its own way and asks to advance. No hook runs a model, and nothing is posted: delivery drafts stay in the run.

Can an agent skip a gate or a step?

Yes. Gates and steps record what was checked and report whether it still holds; on their own they block nothing, so a gate never run shows as open and a skipped step shows as skipped, with a reason and a name. A guard rule you add can deny or ask about a command such as git commit until the gates are met; it is a guard, not enforcement, and only sees the tool calls Claude Code shows it.

Is it formally verified?

In part. Three decision kernels (the run graph, gate obligations and the Weft assessed gate) are proved in Lean over an Aeneas translation of the Rust that ships; the proofs trust that translation and the Lean kernel. The write protocol and the run graph are model-checked with TLC at small bounds, not proved: the models are hand-written evidence about the design, not a refinement of the Rust, and the widest run-graph configuration was stopped unfinished with no violation found. The rest (parsers, file and Git reads, scope globs) is tested. The numbers and limits are in the assurance guide.

Other harnesses?

The CLI works wherever an agent has a shell. An MCP server is deferred until a harness without a shell needs one.

Is the source available?

Yes: Writfold, Weft and Splicery are public, and this website is under the MIT license.
