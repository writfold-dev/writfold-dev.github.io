01 / Runs today

In the preview

From v0.3.0-dev.1, a static Linux x86_64 binary with a .sha256 file. Try it, or read the README.

Read verbswritfold kb brief | context | why | status | find | match | impact | uses | timeline | stale | resume | runs over plain Markdown and JSON records in Git. Every answer ends with a coverage line: what was examined, what was omitted, and whether any cited source is stale. find tolerates a typo; impact states how far it searched→Write verbscheckpoint, record ticket|decision|link, status --set and cite make write plain files atomically and leave them uncommitted→Index and citationsA local SQLite index derived from Git; index verify checks it equals a rebuild. Each citation pins path@commit:lines with a digest, and stale reports it fresh, moved, changed or gone→Retrieval with Tuftwritfold tuft run --cite finds exact text or a bounded regex at one pinned commit, within an output budget. Each row carries a citation token, and a search inside a run is kept as a retrieval receipt→Edits with Splicerykb edit apply replays Splicery recipes against the run’s worktree, uncommitted edits included. If any recipe or file fails, nothing is written; otherwise each file is written atomically after a re-check, and an edit receipt is kept. A crash between files leaves a journal that kb edit recover finishes→Gates with pinned receiptskb gate run | status | verify | lines | attest | waive. A gate is a small TOML file naming a command and the paths it covers. Each receipt is pinned to the exact bytes in scope, and the state is derived on every read: open, satisfied, stale, failed, unknown, attested or waived. An attested gate runs nothing and is met by a recorded statement. A timeout or crash is never a pass. Writfold’s own pushes to main go through kb gate run, with the receipt lines in the commit message→Delivery draftskb deliver prepare | check | status | attest | waive keeps a PR comment or Slack summary in the run as the exact text to post, checked for paragraph length, references denied for the audience and fresh citations. Editing a draft makes its checks stale. Nothing is ever sent→writfold watchA read-only terminal view of runs, checkpoints, gate states, receipts and drafts, built only from the same verbs. --once prints one frame as text→Claude Code pluginA project brief at session start with no tool call, local checkpoint drafts before compaction and at stop, and one skill. An optional PreToolUse hook, off unless configured, denies a listed publishing command unless a ready draft holds the exact bytes: a guard, not enforcement→

Measured: reads at most 45 ms on 4,130 records; writes about 120–130 ms. Writes of checkpoints, receipts, edits and drafts killed at every step leave the old or the new complete state. A TLA+ model of the write protocol passes, and its five mutants fail.

Limits: single user with cooperating agents; local clones only. The delivery checks are covered by tests and demo runs; no real PR comment or Slack summary has gone through them yet.

02 / Roadmap

In order

The intended flow is on How it works, with the same labels.

  1. The four questions

    Read and write verbs, the rebuildable index with typo-tolerant search, pinned citations and stale, and the Claude Code plugin. Done

  2. Runs with gates, edits and drafts

    Gates with pinned receipts, statements, Splicery edits in a run, Tuft citations and retrieval receipts, delivery drafts, writfold watch and the optional guard hook. Done

  3. Instruction gates and your own delivery modes

    A gate can point to an .md file of instructions and come with its own scripts. A delivery mode, such as a commit message, is a small file listing its gates. Next

  4. Plans and plan advance

    plan set | status | advance: a plan in the run lists steps and the gates each one owes, and advance refuses until the current step’s gates are met. Plan templates live under .writfold/plans/, and a skill names one in a line. Planned

  5. Weft plan verification

    A plan step can require a Weft assessment of its assumptions and checks, with assumptions backed by Writfold receipts and citations. Planned

  6. A two-week pause

    Use it on real work and count what the checks caught before adding more. Planned

  7. MCP

    The same answers over MCP, for other harnesses. Planned

  8. Trailer and tracker edges, and --at

    Links derived from commit trailers and tracker references, and reads at an earlier commit. Planned

04 / FAQ

Common questions

Can I use Writfold today?

Yes, as a preview: download the binary and install the plugin. It is for a single user with cooperating agents, reads local clones only and never fetches, and runs on Linux x86_64 or WSL2.

Does it need a server or a database?

No. It is one static binary, project memory as plain records in Git, and a local index that Writfold derives and can always rebuild. A new machine needs git clone plus the binary. No hosted service or account.

Does it replace my coding agent?

No. The agent keeps its own loop and model, and asks Writfold about the project. The Claude Code plugin works today; MCP is planned.

When should an agent use Tuft or Splicery?

Tuft when the question is about the code at a known commit and the answer should carry citations; kb find when it is about the project’s records. Splicery when an edit repeats or has structure; ordinary Edit, grep and sed for one small change. Both tools are maintained; new language features are not a priority.

Does Writfold post PR comments or Slack messages?

No. kb deliver keeps drafts with their checks in the run; nothing is ever sent, and there are no Slack or PR adapters.

Can an agent skip a gate?

Gates record what was checked and report whether it still holds; on their own they block nothing. Receipts resist mistakes, not adversaries: they are tracked files, so an edited one shows in Git history and gate verify, but nothing is signed. The optional hook is a guard, not enforcement.

Can a gate be a judgement, such as “the wording is clear”?

Only as a statement. An attested gate records who said so, about which bytes, and is shown as attested, never as passed. Writfold runs no model and does not judge tone or truth.

Can a skill require gates?

Not yet. Today every gate defined for a repository is owed by every run on it, and a skill can only tell the agent which to run. Plan steps that name their gates, started from a template a skill names, are planned.

Does Weft check plans today?

No. Weft verifying a plan step is planned. Today a plan is a checkpoint note in the run.

Is the source available?

Yes. The Writfold, Weft and Splicery repositories are public, and this website is public under the MIT license.
