01 / Runs today

Project continuity, then frozen demos

From the preview v0.3.0-dev.1, a static Linux x86_64 binary with a .sha256 file. Try it.

Read verbswritfold kb brief | context | why | status | find | match | impact | uses | timeline | stale | resume | runs over plain Markdown and JSON records in Git. Every answer ends with a coverage line: what was examined, what was omitted, and whether any cited source is stale. find tolerates typos; impact states how far it searched→ Write verbscheckpoint, record ticket|decision|link, status --set and cite make write plain files atomically and leave them uncommitted→ Index and citationsA local SQLite index derived from Git; index verify checks it equals a rebuild. Each citation pins path@commit:lines with a digest, and stale reports it fresh, moved, changed or gone→ Gates with pinned receiptskb gate run | status | verify | lines | attest | waive. A gate is a small TOML file naming a command and the paths it covers. Each receipt is pinned to the exact bytes in scope, and the state is derived on every read: open, satisfied, stale, failed, unknown, attested or waived. A timeout or crash is never a pass. Writfold’s own pushes to main go through kb gate run quality and unit, with generated receipt lines in the commit message→ Splicery edits in a runkb edit apply replays Splicery recipes against the run’s worktree, uncommitted edits included. If any recipe or file fails, nothing is written; otherwise each file is written atomically after a re-check, and an edit receipt is kept. A crash between files leaves a journal that kb edit recover finishes→ Delivery draftskb deliver prepare | check | status | attest | waive keeps a PR comment or Slack summary in the run as the exact candidate payload, checked for paragraph length, references denied for the audience and fresh citations. Editing a candidate makes its checks stale. Nothing is ever sent→ writfold watchA read-only terminal view of runs, checkpoints, gate states, receipts and drafts, built only from the same verbs. --once prints one frame as text→ Claude Code pluginA project brief at session start with no tool call, local checkpoint drafts before compaction and at stop, and one skill. An optional PreToolUse hook, off unless configured, denies a listed publishing command unless a ready draft holds the exact bytes: a guard, not enforcement→

Measured: reads at most 45 ms on 4,130 records; writes about 120–130 ms. Writes of checkpoints, receipts, edits and drafts killed at every step leave the old or the new complete state. A TLA+ model of the write protocol passes, and its five mutants fail.

Frozen demos

From earlier work, built from source. They still build and run, and get no new development. Tuft and Splicery are reachable from the preview through their adapters.

Tuft v0Exact text or bounded regex over one pinned commit, kept as citations bound by digest. writfold tuft run --cite now adds the same citation tokens to its rows and records searches as receipts in the current run→ The edit trialA cooperating single-user flow on any Git repository: retain exact evidence, prepare an edit, approve, apply and recover, each step in a validated ledger kept in Git→ WeftLocal checks of what declared assumptions support: entailed, refuted or undetermined→ SpliceryByte-exact edit preview that never touches the original file. writfold kb edit apply now replays its recipes in a run’s worktree→

A few decision kernels in these demos are proved over the shipped Rust with Charon/Aeneas and Lean; the rest is tested, not proved (how we know). Build commands are on earlier work.

02 / Roadmap

In order

  1. Read verbs, index and impact (M1–M2)

    brief, why, context, stale and the rest; the rebuildable SQLite index with typo-tolerant search; links between records to answer what changing X touches. Done

  2. Writes and checkpoints (M3)

    Checkpoints, records and status changes as plain files, written atomically. Done

  3. Claude Code plugin and Tuft adapter

    The brief and checkpoint drafts in a session; citation tokens and retrieval receipts from Tuft. Done

  4. Gates with pinned receipts

    A check that Writfold runs itself, with one receipt per evaluation pinned to the exact commit and paths it judged. The receipt goes stale when that subject moves. Done

  5. Splicery adapter for big edits

    A Splicery recipe applies in a run’s recorded worktree; the result is an ordinary Git change judged by a gate, with the recipe and preview kept as a receipt. Done

  6. writfold watch

    A read-only terminal view of runs, gates, receipts and drafts. Done

  7. Offline PR and Slack drafts

    Delivery drafts kept in the run with their checks, never sent, and an optional guard hook. Done

  8. A two-week pause

    Use the preview on real work and see whether the checks catch real problems before adding more. Next

  9. MCP

    The same answers over MCP. Planned

  10. Trailer and tracker edges, and --at

    Edges derived from commit trailers and tracker links, and reads at an earlier commit with --at. Planned

Paused: the Dolt and Omnigraph backends explored earlier, and benchmarking. Earlier pilots found no measurable win over ordinary tools.

04 / FAQ

Common questions

Can I use Writfold for project continuity today?

Yes, as a preview: download the binary and install the plugin. It is for a single user with cooperating agents, reads local clones only and never fetches, and runs on Linux x86_64 or WSL2.

Does it need a server or a database?

No. It is one static binary, project memory as plain records in Git, and a local index that Writfold derives and can always rebuild. A new machine needs git clone plus the binary. No hosted service or account.

Does it replace my coding agent?

No. The agent keeps its own loop and model, and asks Writfold about the project. The Claude Code plugin works today; MCP is planned.

Does Writfold post PR comments or Slack messages?

No. kb deliver keeps drafts with their checks in the run; nothing is ever sent, and there are no Slack or PR adapters.

Can an agent skip a gate?

Gates record what was checked and report whether it still holds; on their own they block nothing. Receipts resist mistakes, not adversaries: they are tracked files, so an edited one shows in Git history and gate verify, but nothing is signed. The optional hook is a guard, not enforcement.

Is the source available?

Yes. The Writfold, Weft and Splicery repositories are public, and this website is public under the MIT license.
