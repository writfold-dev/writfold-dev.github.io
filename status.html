02 / Roadmap

Done, planned, and not planned

  1. Questions, records and citations

    The read and write commands, pinned citations, external checkers and the Claude Code plugin. Done

  2. Gates and delivery drafts

    Receipts tied to exact bytes, statements, checklists and checked drafts. Done

  3. Plans and guard rules

    Plan templates, skills that add steps, required steps and guard rules. Done

  4. writfold watch

    The plan and the project’s records in one terminal view. Done

  5. A delivery mode as a step’s gate

    A plan step that owes a checked draft. Done

  6. Your policy

    Which outcomes meet a gate, steps that cannot be skipped, policy pinned per run, and a plan that says how it finished. Done

  7. Delivery modes for agents

    A mode says which checks may be waived; the guard reads the exact text being posted; citations are stripped from outward text; posts are recorded. Done

  8. Re-pinning

    plan repin to accept an edited policy mid-run, on the record. Done

  9. Several agent sessions at once

    A current run per session and per work tree, and hand-overs with resume --here. Done

  10. Attached stores

    A companion repository of evidence, declared once and cited at its pinned commit. Done

  11. Run artifacts

    checkpoint --artifact: a run keeps pinned pointers to what it made in a store, shown by resume. Done

  12. Evidence that answers its item

    Checklist items that need their own evidence, gates that age, scopes across repositories, and looks that found nothing pinned to what they searched. Proved in Lean. Done

  13. Stores that point back

    A store directory names the record it serves, and kb context and kb uses list it. Done

  14. Snapshots of a look

    observe --snapshot keeps the bytes an agent saw in a store, so a record shows what it relied on. Proved in Lean. Done

  15. Stemming and exact lookups

    find stems English words, stops after an exact ID under --limit, and session start shows the records the branch names. Which hits become rows is proved in Lean. Done

  16. Store evidence on another machine

    A committed record of pinned store verdicts, so a clone without the store can still read them. Proved in Lean. Done

  17. Aliases

    A Markdown record lists the other names people call it; find answers them and a reference to one links to the record. Done

  18. The same warning on every clone

    brief, context, why and session start show a committed checker verdict as the gates do, before any local check. Done

  19. Help for each command

    writfold kb <verb> --help, suggestions for a mistyped verb or flag, and --color. Done

  20. Gate checks a receiver can trust

    An unreadable gate directory is never read as empty, and handoff check judges the gates an operator requires on the candidate, whatever the agent’s plan said. Proved in Lean. Done

  21. Large knowledge bases

    Rebuild and verification in constant memory, refreshes that rewrite only the links an edit affects, and graph answers that read a bounded number of links. Proved in Lean; the index repair is model-checked. Done

  22. Loops

    A plan step repeats a template until its gates pass: a script, a checklist, a reviewer’s word or a count, with a required cap. plan again records each round; running out is never shown as passing, and a Stop rule can go quiet on a spent loop. Proved in Lean and model-checked. Done

  23. Asset catalogs

    A project’s JSON inventory becomes a reviewable Git patch of ordinary asset records; incomplete or conflicting input never patches. Proved in Lean. Done

  24. Retained gate evidence

    A gate keeps the report its checker wrote, committed with the run and bound to the receipt; missing or edited evidence never passes. Proved in Lean. Done

  25. An optional Plyrune check

    An external checker as an ordinary gate, through a small wrapper; nothing needs Plyrune unless you configure it. Exercised on stand-in reports: Plyrune is unreleased, and checking report fields waits for the agreed profile. Done

  26. The handover packet

    resume --packet: required rows first, cut to a budget, complete only when nothing required was cut. Proved in Lean. Done

  27. Prose rules for drafts

    Phrase and pattern rules kept as data in the repository; advice is shown and recorded and never decides, a blocking match fails, and an empty rule set is never a pass. A script check’s findings are kept as advice when it passes. Proved in Lean. Done

  28. Pages past the work limit

    Resumable pages over a large graph answer. Planned

  29. Lessons in the handover

    An accepted lesson, scoped to a project, shown to a fresh session with its source and freshness. Planned

  30. Revising a plan mid-run

    Replace the rest of a run’s route without dropping a required step or gate. Planned

  31. Comparing loop rounds

    Say whether a round checked the same thing with the same result as the last one. Planned

  32. External prose linters

    A recipe that runs a pinned linter such as Vale on a draft and keeps its report with the check. Planned

  33. Citations as links

04 / FAQ

Common questions

Can I use Writfold today?

Yes, as a preview: install it on Linux x86_64 or WSL2. It is built for one person and their agents, working on local clones.

Does it need a server or a database?

No. One static binary and files in Git. Writfold keeps a local index for speed and can always rebuild it from Git.

Does Writfold run or schedule my agent?

No. It records the plan and what met each gate. The agent reads the current step, does the work its own way and asks to advance. Writfold runs no model and posts nothing.

Can an agent skip a gate or a step?

Yes, and it shows. A gate never run shows as open; a skipped step shows as skipped, with a reason and a name. Your policy can narrow this: a gate can refuse a waiver, and a required step can refuse a skip. A guard rule you add can deny a command such as git commit until the gates are met. It is a guard, not a lock: it only sees the commands Claude Code shows it.

Is it formally verified?

In part. The decisions about plans, gates, checklists, delivery drafts, guard rules, your policy, which run is current for a session, how a store’s citations are judged and whether a checklist item’s evidence answers it and still holds, such as whether a step may be recorded as done and whether a receipt is still about the present bytes, are proved in Lean for every input, against the Rust that ships. The code that reads files into those decisions is tested, not proved. The assurance guide has the details and the limits.

Other harnesses?

The CLI works wherever an agent has a shell. The session-start brief and the guard rules come with the Claude Code plugin.

Is the source available?

Yes: Writfold is public, and this website is under the MIT license.
