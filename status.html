01 / Runs today

Frozen demos

From the source-only preview v0.1.0-dev.1, built from source on Linux x86_64 and WSL2. They still build and run, and get no new development.

The edit trialA cooperating single-user flow on any Git repository: retain exact evidence, prepare an edit, approve, apply and recover, each step in a validated ledger kept in Git→ Tuft v0Exact text or bounded regex over one pinned commit, kept as citations bound by digest, with explicit omissions. Its output contract carries into the first slice→ WeftLocal checks of what declared assumptions support: entailed, refuted or undetermined→ SpliceryByte-exact edit preview that never touches the original file→

A few decision kernels in these demos are proved over the shipped Rust with Charon/Aeneas and Lean; the rest is tested, not proved (how we know). Build commands are on earlier work.

02 / Roadmap

In order

  1. First slice

    Four read-only commands over a knowledge base of plain Markdown and JSON records in a Git repository: brief (where do we stand), why (why did we decide X), context (what is around one thing) and stale (which sources have moved). Every answer is to name its source, a path at a commit with a digest, and say when that source has moved. Implementation started 11 Nov

  2. Index and fuzzy search

    A local SQLite index derived from the records in Git and kept in sync by Writfold, so it can always be rebuilt, with typo-tolerant text search. Planned

  3. Derived edges and impact

    Links between records, derived from the records themselves, to answer what changing X touches. Planned

  4. Writes and checkpoints

    Recording decisions and progress back to Git as plain records. Planned

  5. Claude Code plugin and MCP

    Bringing the same answers into an agent session directly. Planned

Paused: the Dolt and Omnigraph backends explored earlier, and benchmarking. Earlier pilots found no measurable win over ordinary tools.

03 / Changelog

What changed

  1. 11 Nov 2026

    New direction: Git-native project continuity for coding agents. Git is the only store, with a local index Writfold derives and can always rebuild. The first slice is designed. The edit trial, Weft and Splicery are frozen as working demos, and Tuft is frozen at v0. The Dolt and Omnigraph backends and benchmarking are paused.

  2. 10 Nov 2026

    One command, writfold trial run, goes from a Tuft query through a Weft check to a prepared edit and stops at approval. Retained evidence can be read back in a later session, verified against its digest.

  3. 9 Nov 2026

    Source-only preview v0.1.0-dev.1: the edit trial runs end to end, and Tuft v0 finds and cites exact evidence. Decision kernels proved over the shipped Rust with Charon/Aeneas and Lean.

  4. 8 Nov 2026

    Repositories made public.

Every published file on this site is listed with its SHA-256 in the content manifest.

04 / FAQ

Common questions

Can I use Writfold for project continuity today?

Not yet. It is planned; the roadmap gives the order. The frozen demos on earlier work build and run from source.

Will it need a server or a database?

No. The plan is one static binary, project memory as plain records in Git, and a local index that Writfold derives and can always rebuild. A new machine needs git clone plus the binary. No hosted service or account.

Does it replace my coding agent?

No. The agent keeps its own loop and model, and asks Writfold about the project. A Claude Code plugin and MCP are planned after the core.

Is the source available?

Yes. The Writfold, Weft and Splicery repositories are public, and this website is public under the MIT license.
