Start with one source

From exact inputs to a recoverable change.

This is the intended end-to-end flow, not an executable quickstart. Control and local artifact paths have been exercised; the owner data and effect services that complete this flow are not yet implemented.

One source, one explicit decision.

For example, retain a runbook exactly as read, assess the declared assumptions with Weft, and have Splicery prepare a source edit. Writfold must authorize that particular edit before its native adapter can apply it.

A successful assessment is not approval. A prepared edit is not a committed change. A process reply is not a durable receipt.

The important distinction

A citation is not approval.

Finding a document does not establish that every statement in it is true. Supporting evidence, contrary evidence, freshness, validation, authority and publication are independent questions.

A context is a boundary.

Evidence or approval in one context must not silently authorize a claim in another. A shared source is not shared permission.

These are product contracts. Complete Rust workflow qualification remains open.

Scribes · planned integration model

Connect a tool with a small script.

A scribe is intended to help Writfold find and read a source: a repository, a document service or your team's tools. Writfold will manage acquisition and retain the returned evidence as an immutable record called a writ.

Next integration boundary

An exact-input-to-receipt alpha

The target is a public experimental alpha using disposable data only. Owner data and effect services, native materialization, durable receipts and same-effect recovery still need end-to-end qualification.

Omnigraph remains the intended backend. A source-built upstream relocation fix is being evaluated as a development unblocker; a draft fix is not an admitted release. Fuzzy discovery is not yet available.
