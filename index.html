Git-native project continuity for coding agents

Project memory in Git
that says when it is stale.

Every new agent session starts without the project’s history. With Writfold, a fresh session on any machine can answer four questions, and each answer names the file and commit it came from.

  • Why did we decide X?
  • Where do we stand on Y?
  • What is the tracker item for Z?
  • What does changing X touch?

How it works

Records in Git, an index you can rebuild, answers you can check

Agent memory features live with one tool, on one machine or account. Notes in Markdown travel, but nothing tells you when the code they describe has changed. Writfold does both. The agent keeps its own loop and model, and asks Writfold about the project.

01

Records in Git

The knowledge base is plain Markdown and JSON records in a Git repository. Git is the only store, so a new machine needs git clone plus the binary.

02

A rebuildable index

A local SQLite index is derived from those records, with typo-tolerant search. kb index verify checks it equals a fresh rebuild.

03

Pinned, flagged when stale

Each citation pins path@commit:lines with a digest. stale reports each one as fresh, moved, changed or gone.

One static binary; no server or database to run. Writes are plain files, left uncommitted for review.

Inside a run

Checks, edits and drafts, kept in the run

A run is one task in one worktree. Its receipts stay in the run and resume shows them, so “where do we stand on Y?” includes what was checked.

01

Gates

A gate names a command and the paths it covers. Each receipt is pinned to those bytes; gate status says satisfied, stale, failed or unknown.

02

Edits

kb edit apply replays Splicery recipes in the run’s worktree: every file or none, recoverable after a crash, with an edit receipt.

03

Drafts

kb deliver prepare keeps a PR comment or Slack summary as the exact payload, with its checks. Nothing is ever sent.

writfold watch shows runs, gates and drafts, read-only. An optional publishing hook, off unless configured, is a guard, not enforcement.

Try it

Download, verify, install the plugin

Linux x86_64 or WSL2. The plugin adds a project brief at session start and keeps local checkpoint drafts.

base=https://github.com/writfold-dev/writfold/releases/download/v0.3.0-dev.1
curl -LO "$base/writfold-x86_64-linux-musl" -LO "$base/writfold-x86_64-linux-musl.sha256"
echo "$(cut -d' ' -f1 writfold-x86_64-linux-musl.sha256)  writfold-x86_64-linux-musl" | sha256sum -c
install -m 755 writfold-x86_64-linux-musl ~/.local/bin/writfold

claude plugin marketplace add writfold-dev/writfold
claude plugin install writfold@writfold

Single user, cooperating agents, local clones only; nothing is fetched. Setup is in the README.
