Git-native project continuity for coding agents

Project memory
that travels with Git.

A fresh agent session, on any machine, should be able to answer four questions:

  • Why did we decide X?
  • Where do we stand on Y?
  • What is the tracker item for Z?
  • What does changing X touch?

Every answer is pinned to its source, a path at a commit with a digest, and flagged when that source has moved.

How it works · planned

Records in Git, an index you can rebuild, answers you can check

The agent keeps its own loop and model, and asks Writfold about the project.

01

Records in Git

Project memory will be plain records in Git. Git is the only repository you need, so a new machine needs git clone plus the binary.

02

A rebuildable index

A local SQLite index will be derived from those records and kept in sync by Writfold itself, so it can always be rebuilt. It will include fuzzy (typo-tolerant) text search.

03

Pinned, flagged when stale

Each answer will name its source: a path at a commit, with a digest of the bytes read. When that source has moved since, the answer says so.

One static binary. No server, and no database to run.

Planned first · in progress

The first slice

Four read verbs over an existing project knowledge base: brief, context, why and stale. After that: the index and fuzzy search, impact across records, writes and checkpoints, then a Claude Code plugin and MCP.
