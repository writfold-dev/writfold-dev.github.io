Git-native project continuity for coding agents

Project memory in Git
that says when it is stale.

Every new agent session starts without the project’s history. With Writfold, a fresh session on any machine can answer four questions, and each answer names the file and commit it came from.

  • Why did we decide X?
  • Where do we stand on Y?
  • What is the tracker item for Z?
  • What does changing X touch?

The plan, as a map

See where the work stands

A run has a plan. Each step owes gates: small checks whose receipts are tied to the exact bytes they checked. writfold watch draws it in your terminal.

✓ Done, and still true
A step is recorded as done only when every gate it owes is met.
! Done, but something moved
A later edit changed the bytes a gate checked. The step stays done and is flagged.
▶ Next
The step to pick up, from the record. It is not a claim that an agent is working.

Read-only: it shows what the records say and starts no check.

One answer

Every line names its source

No server

Plain records in Git, and one binary

Git is the source of truth

Decisions, tickets, runs and receipts are Markdown and JSON files. Writes are left uncommitted for you to review.

The index is derived

A local SQLite file, rebuilt from Git whenever needed. A new machine needs git clone and the binary.

It records and reports

Your agent keeps its own loop and model. Gates block nothing unless you add a guard rule.

Try it

Download, verify, install the plugin

Linux x86_64 or WSL2.

base=https://github.com/writfold-dev/writfold/releases/download/v0.5.0-dev.7
curl -LO "$base/writfold-x86_64-linux-musl" -LO "$base/writfold-x86_64-linux-musl.sha256"
echo "$(cut -d' ' -f1 writfold-x86_64-linux-musl.sha256)  writfold-x86_64-linux-musl" | sha256sum -c
install -m 755 writfold-x86_64-linux-musl ~/.local/bin/writfold

claude plugin marketplace add writfold-dev/writfold
claude plugin install writfold@writfold
