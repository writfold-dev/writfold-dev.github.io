Writfold keeps a coding agent’s plan, checks and decisions as plain files in Git.

Deterministic

Not the model: the process around it. The agent follows a plan; each check leaves a receipt tied to the exact bytes it checked; and what is done, what is owed and whether a step may close are computed from files in Git, the same on every machine.

Deterministic

A plan the agent walks, with checks that leave receipts

What the agent writes is its own; what Writfold says about it is derived from the records, never from a model.

Each task is a run with a plan. Each step names its gates: checks you define, such as your tests. writfold watch shows the plan in your terminal.

✓ Done, and its checks still hold
A step is recorded done only when every gate it owes is met. A gate met by a statement or a waiver is shown as attested or waived, never as passed, and a step whose checked bytes have since changed is flagged stale.
! Done, but something moved
A later edit changed the bytes a gate checked.
▶ Next
The step to pick up.

A finished plan says how it finished: complete, complete-with-exceptions, policy-moved.

Gates report; they block nothing by themselves. A guard rule you add can deny a command such as git commit until they are met, and your policy says which outcomes meet a gate.

Resumable

A new session reads a brief, not the project

Three commands carry work from one session to the next.

kb checkpoint
Writes a note into the run for the next session.
kb resume
Shows where the run stopped: its last notes, plan step and owed gates.
kb brief
Shows where the project stands. The Claude Code plugin adds it at session start.

The agent can also ask why something was decided. Every line of the answer names its source, and says so when that source has moved.

No server

Plain files in Git, and one binary

Git is the source of truth

Decisions, tickets, runs and receipts are Markdown and JSON files. Writfold writes them and leaves the commit to you.

Nothing else to run

No server and no account. A new machine needs git clone and the binary.

Your agent stays yours

It keeps its own loop and model. Writfold records and reports; it runs no model and sends nothing.

Try it

Install

Linux x86_64 or WSL2.

$ curl -fsSL https://writfold.dev/install.sh | sh

The installer prints its plan first, with every path it will touch. Then it:

  • downloads writfold-x86_64-linux-musl and its .sha256 from the GitHub release into a temporary directory;
  • checks the SHA-256 before installing anything;
  • writes one file, ~/.local/bin/writfold;
  • asks before adding the Claude Code plugin. That step runs the claude CLI, which writes under ~/.claude. With no terminal to ask on, it is skipped and the two commands are printed.

It does not use sudo and does not edit your shell startup files. Read the script, or see the plan without installing:

$ curl -fsSL https://writfold.dev/install.sh | sh -s -- --dry-run

Options: --no-plugin, --plugin, --yes, --prefix DIR, --version V.

Prefer to do it by hand? 
base=https://github.com/writfold-dev/writfold/releases/download/v0.6.0-dev.11
curl -LO "$base/writfold-x86_64-linux-musl" -LO "$base/writfold-x86_64-linux-musl.sha256"
echo "$(cut -d' ' -f1 writfold-x86_64-linux-musl.sha256)  writfold-x86_64-linux-musl" | sha256sum -c
install -m 755 writfold-x86_64-linux-musl ~/.local/bin/writfold
claude plugin marketplace add writfold-dev/writfold
claude plugin install writfold@writfold

These are the same steps the installer performs.
