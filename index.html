A local knowledge engine for coding agents

Keep the context.
Know what supports it.

Writfold lets a coding agent keep exact copies of what it read, check what those sources actually support, and change files only through edits you have approved, with a receipt it can recover from.

Why

What Writfold is for

Agents forget between sessions, and a summary loses where a fact came from. Writfold is designed around three goals.

01 /

Keep the evidence.

Store the exact bytes and revision behind a claim, so a reference leads back to what was actually read, not to whatever the URL holds today.

02 /

Approve what changes.

Knowledge and file edits are proposed first and applied only with an explicit, recorded approval.

03 /

Carry context forward.

Ask for a bounded view of a named context, with its evidence, contradictions and gaps, without mixing work and personal authority.

The core idea

Found, supported, approved: three different things.

Finding a document does not make it right, and a document being right is not permission to act on it. Writfold records each of those as a separate step.

The same holds across contexts: evidence or approval in one context never silently authorizes anything in another.

How it works

The six steps

Writfold is the owner: it alone holds the knowledge store and alone changes files. Weft and Splicery only read and propose. Steps 2 and 3 run today as standalone tools; the rest are being built.

Three tools

Three tools, one approval boundary

Each tool has one job. Only Writfold can change anything.

Writfold

Stores exact evidence, holds the approval policy, and is the only component that writes files or publishes knowledge.

writfold serveToday: stdio session start and shutdown only.

Weft

A small language for stating assumptions and checks, then reporting which checks follow. Its reports carry no write permission.

check docs_only: has_plan("payments");Today: local assessment runs.

Splicery

A small language for byte-exact edits. It computes a candidate file and never touches the original.

replace @expr with ["not ", keep(@expr)]Today: offline preview runs.

Status

What runs today

Runs

Tools and tested parts

The Weft and Splicery examples on this site run with development binaries. The writfold binary starts a stdio session and refuses everything else. Separately tested parts cover exact object storage, an Omnigraph data path, Git worktree creation, ledger-head decoding and procedure checking.

Test record: 12 real-process scenarios across 29 invocations, plus 8 coverage tests.

Not yet

The connected flow

The parts are not yet connected, so the six steps cannot run end to end. Four scenarios that need those services stay blocked: shared evidence handoff, approved edits, crash recovery and session benchmarks.

The next milestone is an experimental alpha for disposable data only.
