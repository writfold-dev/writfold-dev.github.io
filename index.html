Git-native project continuity for coding agents

Project memory in Git
that says when it is stale.

Every new agent session starts without the project’s history. With Writfold, a fresh session on any machine can answer four questions, and each answer names the file and commit it came from.

  • Why did we decide X?
  • Where do we stand on Y?
  • What is the tracker item for Z?
  • What does changing X touch?

The flow

Research, plan, execute, deliver. Each stage leaves a record.

The agent keeps its own loop and model. At each stage it picks a tool, and what it found, checked or drafted goes back into the knowledge base. The next session, on any machine, starts from there.

The knowledge base is plain Markdown and JSON in Git, with a local index Writfold can always rebuild. One static binary; no server. Walk through the four stages.

Pick per task

Two ways to retrieve, two ways to edit

They work side by side. The agent chooses by the task in front of it.

Retrieval

writfold kb find
Records in the knowledge base: decisions, tickets, assets. It tolerates a typo.
writfold tuft run --cite
Exact text in code at a pinned commit, within an output budget. Each row carries a citation that later shows whether its lines moved.

Retrieval in the flow

Edits

Splicery recipes, through writfold kb edit apply
Repeated or structural edits, replayed exactly: an expected count, every file or none, a receipt in the run.
Ordinary Edit, grep and sed
One small change. Simpler, and the result is the same kind of Git change.

Inside a run

Gates, evidence, and what is still owed

A run is one task in one worktree. Each gate result is kept there, so “where do we stand on Y?” includes what is still owed.

01

Gates

A gate is one small check: a file naming a command and the paths it covers, or a statement someone must make.

02

Evidence

gate run keeps a receipt for the exact bytes checked. A statement is recorded as attested or waived, never as a pass.

03

What is owed

resume lists each gate as satisfied, stale, failed or open, with the next command. Draft PR comments and Slack summaries carry their own checks; nothing is sent.

Gates report; they block nothing. writfold watch shows it all, read-only.

Planned Gates with written instructions, your own delivery modes such as a commit message, and plan steps the agent advances through once their gates are met. How gates fit together.

Try it

Download, verify, install the plugin

Linux x86_64 or WSL2. The plugin adds a project brief at session start and keeps local checkpoint drafts.

base=https://github.com/writfold-dev/writfold/releases/download/v0.3.0-dev.1
curl -LO "$base/writfold-x86_64-linux-musl" -LO "$base/writfold-x86_64-linux-musl.sha256"
echo "$(cut -d' ' -f1 writfold-x86_64-linux-musl.sha256)  writfold-x86_64-linux-musl" | sha256sum -c
install -m 755 writfold-x86_64-linux-musl ~/.local/bin/writfold

claude plugin marketplace add writfold-dev/writfold
claude plugin install writfold@writfold

Single user, cooperating agents, local clones only; nothing is fetched. Setup is in the README.
