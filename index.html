Start with one source

From a useful note to inspectable context.

This is the intended local workflow, not an executable quickstart. Production commands and a tested demo will accompany a qualified release.

  1. Choose a named context.

    Decide which project's knowledge and authorization policy you are working within.

  2. Capture the source.

    Retain exact evidence and its identity. Acquisition records what was obtained; it does not approve a claim.

  3. Propose, then approve.

    Connect a proposed claim to evidence. Assess support and contrary evidence separately, then obtain the approval required by that context.

  4. Publish and retrieve.

    Publish the authorized change with recoverable history. Retrieve a bounded context that keeps its evidence and unresolved gaps visible.

The important distinction

A citation is not approval.

Finding a document does not establish that every statement in it is true. Supporting evidence, contrary evidence, freshness, validation, authority and publication are independent questions.

A context is a boundary.

Evidence or approval in one context must not silently authorize a claim in another. A shared source is not shared permission.

These are product contracts. Complete Rust workflow qualification remains open.

Scribes · planned integration model

Connect a tool with a small script.

A scribe is intended to help Writfold find and read a source: a repository, a document service or your team's tools. Writfold will manage acquisition and retain the returned evidence as an immutable record called a writ.

The production scribe host, SDK and catalog workflow are not released. Generated scripts are not automatically trusted. No storage-backend integration is claimed by this site.

Work in progress

A real foundation. Not a finished product.

Writfold is the Rust successor to kctx. The reference history is preserved; historical Python behavior is not a claim that the Rust product is complete.

Implemented foundations

Domain, wire & runtime boundaries

The workspace includes checked nominal identities, bounded typed JSON, canonical signed operations, protocol admission, filesystem primitives and byte-preserving source syntax.

The development writfold-ref host supports conformance work. It is not the production CLI.

Still being qualified

Semantics & complete workflows

Broader Rust semantic proofs, operational protocols, storage, publication and recovery, scribes, production CLI and release packaging remain open.

There is no production install command or downloadable release advertised here.

Evidence has a scope.

Selected foundations have source-bound development evidence. Those results do not qualify the new Omnigraph backend or complete Rust workflows. The implementation and detailed records are currently private; no public release assurance package is available yet.
