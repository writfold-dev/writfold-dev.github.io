How it works

Four stages.
A record of each.

Writfold follows a piece of work from research to delivery. At each stage the agent picks the tool that fits, and what it learned goes back into a knowledge base in Git. This page walks the flow with real commands, and marks what is planned.

Knowledge base1 Research2 Plan3 Execute4 DeliverGatesConfiguration

The base

Records in Git, an index you can rebuild

The knowledge base is a Git repository of plain Markdown and JSON: decisions, tickets, assets, links between them, and one folder per run. Git is the only store, so a new machine needs git clone and the binary.

01

Every row names its source

Each line of an answer ends in @path:line. The last line says what was examined, what was omitted and how many sources are stale.

02

Citations are pinned

A citation pins path@commit:lines with a digest. kb stale reports each one as fresh, moved, changed or gone, against local clones.

03

The index is derived

A local SQLite index speeds up search. kb index verify checks that it equals a fresh rebuild.

Writes are plain files left uncommitted, for you or the agent to review and commit. With the Claude Code plugin, a session starts with brief and resume already in context.

Stage 1 / Research

Ask the knowledge base, or search the code

Two kinds of retrieval, for two kinds of question.

The kb verbs

For what the project already knows. find searches records by words, a partial ID or a typo. why gives the accepted decision and its reasons. context gathers everything around one record. impact walks the links to show what a change touches, and says how far it walked.

Tuft

For what the code says. A short Tuft program finds exact text or a bounded regex at one pinned commit and prints rows within an output budget, with a cursor for the rest. With --cite, each row carries a citation token for its lines.

Planned Not built yet.

Plans with steps

plan set copies a plan into the run. Each step names the gates it owes. plan status shows the current step and what it still owes, and plan advance moves on only when those gates are met. A plan can start from a template in .writfold/plans/ that a skill names.

Weft verifies a plan step

A step can require a Weft assessment. The agent writes the step’s assumptions and checks in a Weft file, and each assumption can cite a Writfold receipt or citation. Writfold confirms those are still fresh, runs Weft, and records the result. A check counts only when it follows from assumptions backed by evidence. One that rests on an unbacked assumption is reported as hypothetical and does not meet the gate.

Stage 3 / Execute

Edit, check, and keep track

The agent edits the run’s worktree, runs the gates, and checkpoints as it goes.

Splicery recipes

For repeated or structural edits: every line matching a pattern, a block between two anchors, the same change across files. A recipe states how many matches it expects and refuses on any other count. kb edit apply replays it on the worktree’s current bytes and writes every file or none. After a crash, kb edit recover finishes the batch.

Ordinary Edit, grep and sed

For one small change. No recipe, no receipt, and nothing in Writfold stands in the way. Either way the result is an uncommitted Git change, and any gate whose scope covers it goes stale until it runs again.

Exact output: the recipe applied

Gates

A gate is one small check, defined in a TOML file. gate run runs its command and keeps a receipt pinned to the commit and the bytes in scope. An attested gate runs nothing: it is met by a statement with a name on it, and is shown as attested, never as passed. A timeout or crash is unknown, never a pass.

Stage 4 / Deliver

Drafts, checked. Nothing sent.

kb deliver prepare copies a PR comment or Slack summary into the run as the exact text that would be posted. deliver check runs three checks on those bytes: paragraph length, references the audience must not see, and whether every citation in it is still fresh.

A failing check names the line and the rule. Editing the draft makes its earlier receipts stale, so it is checked again. Writfold has no network code and no Slack or PR adapter: posting stays with you or your agent.

Into the knowledge base. The draft itself and one receipt per check, kept in the run.

The checks are mechanical. They do not judge tone or truth, and they miss a claim made without a citation. An optional Claude Code hook, off unless configured, can deny a listed publishing command until a ready draft holds the exact bytes: a guard, not enforcement. Planned Your own delivery modes, such as a commit message.

The thread

Gates, evidence, then the next step

Gates are the atomic checks. Runs and delivery drafts owe them. Evidence that Writfold records meets them. The agent submits drafts, statements and plans; Writfold writes every receipt.

Runs today

Command gates and attested gates. Receipts and statements pinned to bytes. Two delivery modes with three built-in checks. Every gate defined for a repository is owed by every run on it, and gate status exits 0 only when all are met.

Planned

Gates that point to written instructions and bring their own scripts. Delivery modes you define, each listing its gates. Plan steps that name their gates, so plan advance moves to the next step once they are met. Skills that start a plan from a template. Weft assessments as evidence for a step.

Gates report; they block nothing. Receipts resist mistakes, such as a forgotten check or a stale “tests pass”. They are tracked files, not signatures.

Configuration

What Writfold reads from .writfold/

Gates and delivery rules are small files in Git, next to the records. A new machine gets them with the clone.

FileWhat it definesState
.writfold/gates/<id>.tomlA gate: a command with a path scope, or an attested gate met by a statement. In the knowledge base or in the repository it checks.Runs today
.writfold/deliveries/<mode>.tomlNarrow a built-in delivery mode: which checks, the paragraph bound, statements it needs.Runs today
.writfold/deliveries/deny-<audience>.tomlReferences a draft for that audience must not contain.Runs today
.writfold/deliveries/guard.tomlPublishing commands the optional guard hook watches. Absent means the guard is off.Runs today
a gate's instructions (.md)A gate names an .md file the agent reads, and ships its own scripts. Editing the instructions makes earlier evidence stale.Planned
.writfold/deliveries/<name>.tomlYour own delivery mode, such as a commit message, listing its gates.Planned
.writfold/plans/<name>.tomlPlan templates. A skill names one in a line of its text.Planned
