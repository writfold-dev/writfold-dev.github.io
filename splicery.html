01 / A precise replacement

Negate one check, not its assumption.

The prerequisite Weft example assumes a recovery plan exists, checks that claim, and independently asks whether restores work. This recipe changes only the first check.

Download negate-check.spl · Download prerequisite review.weft. Save both files together.

edit "review.weft" {
  @goal := one text "check docs_only: has_plan(\"payments\");"
  @expr := one text "has_plan(\"payments\")" within @goal
  replace @expr with ["not ", keep(@expr)]
}

Bind the whole check.

@goal names the unique original-byte span containing the complete docs_only check. It is a local recipe binding, not an authorization token.

Narrow the search.

@expr selects the expression within @goal. The same expression also occurs in the assumption; the bounded search leaves that occurrence alone.

Keep exact bytes.

keep(@expr) copies the captured original bytes into the replacement after "not ". It does not reformat or regenerate the expression.

Coordinates are zero-based byte offsets into the frozen original, not editor columns or UTF-16 positions. Selectors and retained spans refer to that original image, not a progressively edited candidate.

02 / Computation, not installation

One candidate. One unchanged source.

The preview reads the source and lowers the recipe to checked byte edits. Candidate bytes go to stdout; the original file stays untouched.

03 / What the executed example showed

A different check. The same uncertainty.

These commands were exercised with pinned development binaries. They are not installer instructions. With both downloaded files in the current directory:

splicery preview --root . negate-check.spl > candidate.weft
weft prove candidate.weft --json

Shell redirection saves stdout as the separate candidate.weft file. It is not a native Splicery apply operation. Preview exited 0, and the original review.weft bytes were unchanged.

Changed check

docs_only: refuted

The candidate asks not has_plan("payments") while the original positive assumption remains. The original check was entailed; its negation is refuted under that same theory.

Independent check

restore_works: undetermined

Nothing in the recipe adds restore evidence. This check remains undetermined, exactly as it was in the original.

Both the original and candidate weft prove commands exited 1. In both assessments: basis=hypothetical, execution=complete, writfold_grounded=false, and effect_authority=false. Complete execution is not successful proof of every check, real-world grounding, or approval to write.

04 / Refuse rather than guess

Exact selection is a constraint.

No match

If the complete check text is absent or has different spacing, one text cannot bind @goal. The recipe refuses instead of choosing similar text.

Ambiguity

Removing within @goal makes this expression match both the assumption and the check. A selector requiring one refuses multiple matches rather than picking the first.

Overlapping edits

A second replacement covering the same original span conflicts with the first. Overlapping edit targets are refused, not silently ordered into a different change.

This is a bounded offline preview, not a claim that every Splicery language feature is available. Unsupported productions refuse rather than falling back. For the broader authority model, read the project workflow guide.
