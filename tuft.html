Tuft · executed example

Find it exactly.
Keep what you found.

In the Writfold harness, Tuft is how evidence is gathered: a small language that searches one pinned commit for exact text, keeps each hit as a citation bound by digest, and prints a compact view under a token budget. Nothing is guessed or summarised.

Frozen demo Exact text and regex over a pinned commit · source-only preview

Since 11 November 2026, Tuft’s query language is frozen at v0. Its output contract, results pinned to one commit and kept as citations bound by digest, with explicit omissions, carries into the read verbs of Writfold’s new direction, project continuity. The preview reaches it through writfold tuft run --cite. Everything on this page still runs as shown.

01 / Four steps

Every call to open(url), cited

The same client.rs as the Splicery example, plus a worker.rs that calls open(url) three more times, committed to a small repository. The program asks for every call, at that exact commit.

Download client.rs · Download worker.rs · Download find-open.tuft. Put the two Rust files in src/ of a Git repository, commit, and replace the commit id with yours.

pub fn fetch_all(urls: &[&str]) -> Vec<Conn> {
    let mut out = Vec::new();
    for url in urls {
        if let Ok(conn) = open(url) {
            out.push(conn);
        }
    }
    out
}

pub fn warm(url: &str) {
    let _ = open(url);
    let _ = open(url);
}

@hits := find text "open(url)" in "src/" at "67fefbdd2a2964581fe777fc07d9714e62a3eb91";
@ev   := retain @hits around lines 0;
@view := project @ev [path, line, excerpt(max_chars: 60)]
           sort [path asc, line asc];
emit @view budget_tokens 400;

Pin the commit.

find searches the tree of one full commit id, never your working copy. Ask again tomorrow and the answer is the same.

Keep the bytes.

retain keeps each matching line's exact bytes as a citation, bound by digest, that a Weft report and an approval can cite.

Say what is missing.

emit prints rows within the token budget and ends with a trailer that always states coverage, how many rows were shown and omitted, and a cursor for the rest.

Search is exact text or a bounded regex. Over a pinned tree that makes it complete: when the trailer says coverage=complete and hits=0, there really is nothing there.

In two pilots against grep-and-read, Tuft's typed, pinned and citable output cost within about 3% of grep's tokens at equal correctness; it does not save tokens on lookups a shell pipeline can reduce. 04 / Refuse rather than guess

When Tuft refuses

Each of these was run against the same repository and exited 1 without printing rows.

Similarity

find similar "open a connection" is parsed and refused with T301. Tuft v0 never emulates it with something fuzzier.

A moving target

at "HEAD" is refused with T206. Refs, abbreviations and HEAD change under you; only a full commit id is accepted.

Overwriting

--out rows.txt when rows.txt already exists refuses before the search runs. A view is written to a new file or not at all.

Tuft v0 has no relevance ordering, no graph follow and no live index, and with the language frozen at v0 none is planned for it. Tuft lives in the Writfold repository; its language reference has the grammar. In the full flow, Tuft finds the evidence, Weft checks the plan against it, Splicery prepares the edit, and Writfold applies it after approval.
